### Generic Snapshot Banner Implementation + Critical Fix (2025-11-20)

Feature #11 is now **fully verified and runtime tested** ✅

#### Phase 1: Generic Implementation
- Extended `TerminalLayoutLogsContainer` with `scrollFollowingState` and `pauseState` props
- Auto-generates snapshot banner when scroll following state is provided
- Auto-generates pause banner when pause state is provided
- Both Showcase and DebugsyLook now use the thin API (just pass state, no manual banner creation)

#### Phase 2: Critical Bug Fix (Scroll Handler Not Attached)
**Problem:** Scrolling 10 items down → new log arrives → auto-scrolls to top → no banner

**Root Cause:**
- `useScrollFollowing` hook returns `handleScroll` function
- **This was never attached** to container's `onScroll` event
- Result: Scroll events never captured, banner never appeared

**Fix:**
1. ✅ Attached scroll handler to `TerminalLayoutLogsContainer`
2. ✅ Enhanced `useScrollFollowing` to support both log orders (ASC/DESC)
3. ✅ Updated scroll detection for DESC order (newest at top)
4. ✅ Configured consumers with `logOrder: "desc"`

**Result:** Feature now works correctly - scroll away → banner appears → stays in snapshot mode ✅

**Benefits:**
- ✅ Consistent behavior across all consumers
- ✅ Less boilerplate (no manual banner creation)
- ✅ Single source of truth for banner logic
- ✅ Showcase remains thin (all logic in lower layers)
- ✅ Supports both ASC and DESC log ordering

### Render Rate Warning Bridge Implementation (2025-11-20)

Feature #14 is now **fully verified** ✅

**What was done:**
- Bridged V1 and V2 display systems for render rate warnings
- Matched V1's single-line display format exactly
- Updated both render rate and mount rate notifiers

**Implementation Details:**

1. **Display System Bridge:**
   - `notifyHighRenderRate()` now calls both systems:
     - V1: `setDebugDisplayContent()` (for backward compatibility)
     - V2: `setDisplayContent()` (Harbuz system)
   - `notifyHighMountRate()` updated for consistency
   - Both use identical single-line message format

2. **Message Format (matching V1):**
   - Single-line format with all info concatenated
   - Example: `"⚠️ High Render Rate Component: DebugsyLook Rate: 0.3 renders/sec Threshold: 15 renders"`
   - Duration: 8 seconds (configurable)
   - Severity: Escalates from "warning" to "error" at 3x threshold

**How It Works:**
1. `useRenderTracker()` detects excessive renders (threshold: 15 for DebugsyLook)
2. Triggers `notifyHighRenderRate()` with component details
3. Single-line message created with all info
4. Notification sent to both V1 and V2 display systems
5. Display components render single-line message with truncation
6. Auto-clears after 8 seconds (respects 3-second cooldown between alerts)

**Benefits:**
- ✅ V1 and V2 both receive render rate warnings
- ✅ Automatic detection of excessive re-renders
- ✅ Identical display format in both UI versions
- ✅ Single-line format fits in compact display panel
- ✅ Smart throttling prevents notification spam

**Files modified:**
- `packages/debugsy/src/debugsy-deps/use-deps.ts` (bridge implementation, single-line format)
